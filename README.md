# Secure Digital Banking & Transaction Management System

A secure backend application for digital banking operations, developed using **Java 21, Spring Boot, Spring Data JPA, PostgreSQL, and Spring Security**.

The system provides REST APIs for user authentication, bank account management, deposits, withdrawals, fund transfers, and transaction history. It also implements JWT-based authentication, role-based access control, database transactions, pessimistic locking, centralized exception handling, and idempotent fund transfers.

## 🔐 Authentication & Security

The application uses **Spring Security with JWT authentication**.

### Authentication Flow

```text
User
  |
  | Login
  v
Auth Controller
  |
  v
Auth Service
  |
  | Verify BCrypt password
  v
Generate JWT
  |
  v
Client
  |
  | Authorization: Bearer <JWT>
  v
JWT Filter
  |
  | Validate token
  v
SecurityContext
  |
  v
Protected API
```

### Security Features

* Passwords are hashed using **BCrypt**.
* JWT tokens are used for stateless authentication.
* Protected APIs require a valid JWT.
* User identity is obtained from the authenticated security context.
* Customer role is assigned during public registration to prevent privilege escalation.
* Account ownership is checked before sensitive account operations.
* Sensitive operations cannot directly modify balances through client-provided values.

## 👤 User Management

### Registration

```http
POST /api/auth/register
```

Users provide:

* Name
* Email
* Password

The application:

1. Validates the request.
2. Checks whether the email already exists.
3. Hashes the password using BCrypt.
4. Assigns the `CUSTOMER` role.
5. Stores the user in PostgreSQL.

### Login

```http
POST /api/auth/login
```

Successful login returns a JWT token.

The token is then sent with protected requests:

```http
Authorization: Bearer <JWT>
```

## 💰 Deposit

```http
POST /api/accounts/deposit
```

The deposit operation:

1. Finds the account.
2. Locks the account row.
3. Verifies account ownership.
4. Checks that the account is active.
5. Validates the amount.
6. Updates the account balance.
7. Creates a transaction record.

Money values are represented using:

```java
BigDecimal
```

instead of `double` or `float` to avoid floating-point precision problems.

---

## 💸 Withdrawal

```http
POST /api/accounts/withdraw
```

The withdrawal operation:

1. Locks the account row.
2. Verifies account ownership.
3. Checks account status.
4. Validates the amount.
5. Checks sufficient balance.
6. Deducts the amount.
7. Creates a transaction record.

If the account does not have sufficient funds, the operation is rejected.

## 🔄 Fund Transfer

```http
POST /api/accounts/transfer
```

Transfers money between two accounts.

The transfer process:

```text
Sender Account
      |
      | Debit
      v
Transaction
      |
      | Credit
      v
Receiver Account
```

The operation is executed inside a database transaction so that the debit and credit are treated as one atomic operation.

### Transfer validations

* Sender and receiver cannot be the same.
* Transfer amount must be greater than zero.
* Sender must own the source account.
* Both accounts must be active.
* Sender must have sufficient balance.
* Both account rows are locked during the operation.

## 🔁 Idempotent Transfers

The transfer API supports an **idempotency key**.

Example:

```json
{
    "senderAccountNumber": "123456789012",
    "receiverAccountNumber": "987654321098",
    "amount": 500.00,
    "idempotencyKey": "TRANSFER-TEST-001"
}
```

If the same request is accidentally submitted again with the same idempotency key, the application can identify the previously processed transaction instead of processing the transfer again.

This helps prevent duplicate payments caused by:

* Network retries
* Client retries
* Duplicate API requests
* Request timeouts followed by resubmission

The idempotency key is stored with the transaction and protected by a database uniqueness constraint.

## 🔒 Transaction Management & Concurrency

Because this is a banking-oriented application, maintaining data consistency is important.

### ACID Transactions

Operations such as transfers use Spring's:

```java
@Transactional
```

This ensures that related database operations are treated as a single transaction.

For example:

```text
Debit Sender
     +
Credit Receiver
     +
Create Transaction Record
```

If an operation fails, the transaction can be rolled back instead of leaving the accounts in an inconsistent state.

### Pessimistic Locking

Account balance operations use a database row lock:

```java
@Lock(LockModeType.PESSIMISTIC_WRITE)
```

This prevents multiple concurrent operations from modifying the same account balance incorrectly.

### Deterministic Locking

During transfers, accounts are locked in a consistent account-number order.

This helps reduce the possibility of deadlocks when two transfers involve the same accounts in opposite directions.

## 🧩 Validation & Exception Handling

The application uses Jakarta Bean Validation for request validation.

Examples include:

```java
@NotBlank
@NotNull
@Email
@Size
@DecimalMin
```

Custom exceptions are used for banking-specific errors.

Examples:

* `AccountNotFoundException`
* `UserNotFoundException`
* `InsufficientBalanceException`
* `DuplicateEmailException`
* `UnauthorizedAccountAccessException`
* `InactiveAccountException`

A centralized `GlobalExceptionHandler` converts exceptions into structured API responses.

Example:

```json
{
    "timestamp": "2026-10-08T19:30:00",
    "status": 400,
    "message": "Insufficient balance"
}
```

## ⚙️ Setup & Installation

### Prerequisites

Make sure the following are installed:

* Java 21
* Maven
* PostgreSQL
* Git
* Postman or another REST API client

### 1. Clone the Repository

```bash
git clone <your-github-repository-url>
cd <project-folder>
```

### 2. Create PostgreSQL Database

Create a database named:

```text
digital_banking
```

### 3. Configure Database

Update your Spring Boot configuration with your PostgreSQL credentials.

Example:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/digital_banking
spring.datasource.username=your_username
spring.datasource.password=your_password
```

Do not commit real database credentials or JWT secrets to GitHub.

### 4. Build the Project

```bash
mvn clean install
```

### 5. Run the Application

```bash
mvn spring-boot:run
```

The application runs on:

```text
http://localhost:8080
```
